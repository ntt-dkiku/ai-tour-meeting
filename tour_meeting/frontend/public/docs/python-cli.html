User Guide > Getting Started

Python CLI

Use the Python entry point when you want to run the meeting engine directly from code, verify behavior outside the browser, or build a small automation around the core library.

Run the example

The repository includes minimal scripts under examples/ that create participants and start a meeting without the web UI. Scripts run inside the backend Docker container, so start the stack with make up first. 

make run SCRIPT=examples/barcelona.py

When to use it

Debug the engine

Use the CLI path when you want to isolate meeting logic from frontend state, browser refreshes, or websocket output.

Prototype quickly

Edit the script to try a new participant set, prompt shape, or turn rule before wiring the behavior into the GUI.

Automate a run

Use the library directly when a meeting should be started from another Python workflow instead of by clicking in the app.

How it relates to the GUI

The CLI and GUI both use the same meeting engine. The GUI adds saved meetings, participant editing, settings screens, and live logs. The Python path is better when you want a compact, code-first view of what the engine is doing.
