Design

AI Tour Meeting is organized around one repeated workflow: configure the meeting, choose the participants, run the conversation, and inspect the result as the engine moves from turn to turn.

Control surface

The GUI keeps navigation, settings, participants, and logs visible as separate working areas. This makes it easier to adjust a meeting while still seeing whether the current run is healthy.

Meeting shape

Settings

Choose the turn rule, balanced turn behavior, provider, and model before launching the meeting.

Participants

Add agents or a human participant, then arrange the order when the selected turn rule uses that order.

Logs

Watch the event stream to confirm speaker selection, model calls, and any configuration errors.

Workflow fit

Use the GUI for normal operation because it stores meetings and exposes every setting in one place. Use direct Python only when you need a code-first path for debugging or automation.
