Agent skills

Skills are reusable instructions for coding agents. Use them when a project workflow is repeated often enough that the agent should not infer it from scratch.

When to create a skill

Create a skill for work that has a stable process, such as updating docs, preparing a release, or changing a repeated backend and frontend contract. Keep one skill focused on one type of work.

What to include

  1. Name the files that usually change.
  2. Describe the order of operations clearly.
  3. List the checks that should run before the change is handed back.
  4. Call out files that should not be committed, such as local meeting data or scratch experiments.

Keep skills current

Update a skill whenever the project layout, commands, or release process changes. A stale skill can be worse than no skill because it makes the wrong workflow look official.
