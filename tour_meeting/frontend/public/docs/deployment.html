Developer Guide

Hosting and release notes

This page covers the practical setup path for both the application and the documentation site. Use it when you want to run the project locally, confirm the docs copy, or prepare the pages for GitHub Pages.

Run the app locally

  1. Start the backend and frontend with make up.
  2. Open the GUI in your browser and verify that the meeting panels and sidebar load correctly.
  3. If you use a local model or API provider, add the keys and model settings before creating a meeting.
  4. Use the GUI to confirm that the Document link opens these pages in a separate window.

Keep the docs copy in sync

The docs are stored as static HTML, so the version served through the GUI should match the version checked into the repository. When you edit a page under docs/, mirror that change to the copy under tour_meeting/frontend/public/docs/.

That keeps the GUI link and the standalone docs pages pointing at the same content while you are developing locally.

Publish to GitHub Pages

Use the docs folder

Publish the HTML files directly from the repository's docs/ folder so the site works without a build step.

Keep relative links

All navigation links use relative paths, which keeps the site portable when it is opened from the repo or hosted from GitHub Pages.

Check the live pages

After publishing, open the site and confirm that the tab bar, sidebar links, and theme toggle behave the same way as they do locally.

Override the URL if needed

The GUI can point to a different docs URL when you want to open the published site instead of the local copy.
