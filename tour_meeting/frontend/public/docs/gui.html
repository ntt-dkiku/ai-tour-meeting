GUI Guide

This page walks through the parts of the interface you will use most often: the sidebar, the meeting settings panel, the participant list, and the log viewer.

Design the GUI

Meeting selection

Switch between meetings from the sidebar when you want to edit a saved conversation or return to a meeting you already started.

Settings

Open the settings area to enter API keys, choose the language model provider, and decide how the meeting should turn between participants.

Document link

Use the Document entry in the app sidebar to open these docs in a separate window while you work.

Random sample

Generate a sample meeting when you want a quick starting point instead of assembling every participant by hand.

LLM settings

Set the provider, model, and keys before you start a meeting. The GUI keeps these settings close to the rest of the meeting controls so you can move between hosted and local models without leaving the browser.

Provider

Choose the model provider that matches your environment, such as OpenAI, Anthropic, Google, or a local runtime.

Keys

Add the matching API key in Settings before launching a meeting so the participants can call the model you selected.

Model choice

Use the model that best fits the balance you want between speed, quality, and cost for the current meeting.

Meeting Settings

  1. Choose a turn rule that fits the style of the meeting.
  2. Keep Balanced Turns on when you want each participant to speak in regular cycles.
  3. Turn it off when you want a freer selection order and are comfortable with repeated speakers appearing sooner.
  4. Save the settings before starting the meeting so the engine uses the values you picked.

Round robin style rotation is already balanced, so the app treats that combination as always on. Random order can be used for either a balanced sample or a fully free form sequence depending on the toggle.

Participants and order

Add the people or agents you want in the meeting, then arrange them in the order that best matches the conversation you want to run. The list can be edited before the meeting starts, and the current order is reflected in the next turn.

If you are experimenting, use a random sample first to see how the engine fills out a meeting. Once the shape looks right, replace the sample with the real participants.

Logs and feedback

Keep the log viewer open while you work. It tells you whether the engine started, which participant was chosen next, and whether an API key or provider setting needs attention.

If you see this Do this
No API key configured Open Settings and add the missing key for the provider you are using.
The order looks wrong Check whether the turn rule is round robin, random, or inviting/facilitating.
A meeting will not start Confirm the backend is running and the participant list is not empty.
